# 固定齿轮姿态下的积分窗口交换

在两级减速器第二级的 1.6 ms 姿态，第 15 步和第 17 步分别作为上一次查询。两段历史抵达的目标位姿完全相同，均识别出四个承载区，区内配对的曲面编号也逐项相同。实验交换的是每个承载区、每一侧曲面在本地参数平面上的积分矩形。候选搜索、分组及接收方的历史缓存均照常运行。

### 力矩随哪一个窗口改变

下表是从动轴力矩，单位 N·m。四个承载区都固定用 12 阶局部条带积分。原 STEP 实体在相同共享弹性力律下的数值参照为 279.075770 N·m。[独立参考](../step-reference.json) · [四组交叉结果、曲面编号和窗口端点](cross.json)

| 到达第 16 步的历史 | 用 15 → 16 的窗口 | 用 17 → 16 的窗口 |
| --- | ---: | ---: |
| 15 → 16 | 278.240671 | 282.482320 |
| 17 → 16 | 278.240671 | 282.482320 |

固定窗口来源后，两段历史返回的合力和力矩各分量逐项相等。固定接收方后，交换窗口使轴力矩改变 **4.241649 N·m**。允许自适应选择阶次时，两个窗口分别给出 278.137238 和 282.388166 N·m，完整重现原来的 **4.250928 N·m** 差异。四区的终止阶次也由窗口决定，分别为 (24, 6, 12, 12) 和 (12, 6, 12, 24)。这将该姿态的历史差异定位到见证点所生成的积分窗口，以及该窗口触发的后续积分选择。

只替换单个承载区也能分解上述固定阶次差值。按查询程序输出的面编号（从 1 起算），用第 17 步历史的窗口替换配对 (130, 9)、(130, 10) 所在区，轴力矩增加 3.629264 N·m；只替换配对 (3, 4)、(4, 4) 所在区，增加 0.612385 N·m。其余两区的窗口相同。两项增量加起来重现整组窗口的交换效应。[逐区干预](cross.json)

### 一个可以单独开关的改动

在目标姿态继续复用粗筛缓存、候选面和连通性路径，但在寻找曲面对内的见证点时跳过“先试上次见证点”这一步，直接从本次查询的候选起点查找。前一个姿态在两种配置下均运行原始算法。这个改动检验的是查找起点的选择，仍可能受到候选集合及其顺序的影响。

在 1.6 ms 姿态，两种历史的试验结果均为 281.784333 N·m，比 STEP 高 2.708564 N·m。两侧历史的条带积分分别从 7,218 和 7,076 次射线查询增加到 9,880 次。同一结果可以带有共同的误差；因此同时检查新姿态上的独立误差和工作量。[试验数据](cross.json)

### 留出姿态

两级分别取四线程冻结 CAD 五秒响应的第 6251、18751、43751 步，各用前一帧与后一帧作为上一查询。六个目标及其邻帧都在历史 25 姿态集之外，步号在本轮结果产生前选定。后帧作为上一查询用于检验顺序敏感性。每个条件重新创建查询进程，只执行给定前序和目标。记录目标姿态上的轴力矩、积分射线次数和见证点试算次数。全新进程直接查询目标的结果作为冷启动对照。[位姿与冻结响应指纹](holdout-poses.json)

| 级 | 主步号 | STEP 力矩（N·m） | 原算法两种历史的力矩差（N·m） | 仅用本步起点的力矩（N·m，两种历史相同） |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 6251 | 43.201 | < 0.000001 | 43.415 |
| 1 | 18751 | 41.221 | < 0.000001 | 41.407 |
| 1 | 43751 | 31.730 | < 0.000001 | 31.776 |
| 2 | 6251 | 159.167 | 1.232 | 158.832 |
| 2 | 18751 | 135.078 | 1.183 | 134.258 |
| 2 | 43751 | 108.242 | 0.504 | 107.524 |

两种策略在全部查询中的区域数均与 STEP 一致。按 6 个姿态 × 2 种历史的 12 次目标查询统计，关闭旧起点使轴力矩绝对误差的最大值从 1.438 降至 0.820 N·m，中位数从 0.234 升至 0.274 N·m。条带积分共调用 20,036 → 18,848 次射线查询（少 5.9%），见证点试算为 6,936 → 6,952 次（多 16 次）。一级的三帧本来就几乎不受历史影响。二级的三帧去除了 0.504–1.232 N·m 的历史差异。表内“相同”表示导出的轴力矩数值相等。[逐姿态载荷与工作计数](holdout.json) · [加密的 STEP 参考](step-refined.json)

对这六帧，跳过旧起点后的两种历史还分别逐分量复现了冷启动的完整载荷。独立 STEP 参考将积分容差从 10⁻⁸ 收紧到 10⁻¹⁰ 后，轴力矩最大变化为 2.81 × 10⁻⁷ N·m。[冷启动](cold.json) · [常规参考](step.json) · [加密参考](step-refined.json)

这项干预足以消除本轮六帧在指定前、后历史间的差异。它对误差和工作量的影响取决于姿态，在 1.6 ms 反例上甚至增加了积分工作。现阶段将窗口交换用作回归诊断，保留冻结基线；是否采用新起点策略还取决于切换区间、完整运动轨迹和计时对照。

### 复现

诊断以 `2c1506e` 构建，与原始自适应姿态试验对应。四线程闭环基线和生产求解入口沿用项目现有配置。以下命令从项目根目录运行，使用独立工作目录。`$parts` 指向四个编译零件，`$solids` 指向四个原始 STEP，`$oracle` 指向支持压力积分的 `nc_cad_distance_benchmark`。在运行 STEP 参照前配置项目的 OCCT 动态库路径。[冻结模型](../../standalone/README.md) · [Python 回放](../../../../../benchmarks/aes/cpu_window_exchange.py) · [探针改动](../../../../../benchmarks/aes/cpu_window_exchange.patch)

```powershell
$root = (Get-Location).Path
$patch = Join-Path $root 'benchmarks/aes/cpu_window_exchange.patch'
git worktree add --detach build/window-source 2c1506e
git -C build/window-source apply $patch
cmake -S build/window-source -B build/window-probe -DNC_WITH_OCCT=OFF -DBUILD_TESTING=ON
cmake --build build/window-probe --config Release --target nc_compiled_poses
$probe = 'build/window-probe/Release/nc_compiled_poses.exe'
$script = 'benchmarks/aes/cpu_window_exchange.py'
python $script cross $probe $parts build/window-probe/cross.json
python $script holdout $probe $parts build/window-probe/holdout.json
python $script cold $probe $parts build/window-probe/cold.json
python $script step-refined $oracle $solids build/window-probe/step-refined.json
python $script step $oracle $solids build/window-probe/step.json
```

每个交换试验先记录原生积分窗口，再按整个承载区的面配对以及曲面侧别和编号逐一导入。自交换用于核对导入能否复现原生结果。固定阶次仍调用与原自适应模式相同的局部条带积分。工作计数仅统计条带内实际调用的射线查询，以及见证点搜索调用的试算；两类操作分开报告。
