# CPU 减速器的预处理与在线热点

同一两级减速器，步长 0.1 ms，仿真 5 s。墙钟和阶段计时取自[不挂采样器的正式运行](../depth-bounds/comparison.json)。函数定位另用保留优化和本程序调试符号的 Release 版本。两个版本都使用原有求解流程。

## 已写入磁盘的几何量

对四个零件分别按原 STEP 形状标识、OCCT 版本和规则查找二进制表。重新启动原探测程序读取这四个零件，每级各读入 12 张基础表，两次均重建 0 张。表的大小包括形状标识和校验信息。[本次缓存清点和加载核验](cache.json)

| 四个零件的合计，十进制 MB | 表中内容 | 在线用途 |
| --- | --- | --- |
| 51.74 | 可转换曲面的 Bézier 控制点、权重及参数域、导数和空间包围范围 | 筛除射线不可能命中的面片，并局部求交 |
| 9.77 | 参数网格中心的位置、法向、裁剪内外、候选和保守包围盒 | 提议当前姿态的候选面对 |
| 17.59 | 分别索引候选点和曲面块的两棵 BVH 节点表 | 按位姿寻找可能接触的局部区域 |
| 11.20 | 基础 12×12 积分规则中通过裁剪的点及有向面积权重 | 对已经确定的承载点求面积和一阶矩 |
| 15.26 | 双三次多项式面片在局部三个方向上的偏差界和导数界 | 排除一组法向短线段，或隔离其在面片内部的交点 |

零件级基础表共 **105.55 MB**。另有按面存放的 24、48、96 阶积分点，共 2,520 个文件、538.40 MB；这与原减速器从空缓存补建高阶规则的增量一致。全部预备表合计 643.95 MB。程序先尝试 12 阶，当前规则无法解析承载区时才升阶，同一面的高阶规则首次使用后保留在内存。[高阶规则的冷、热缓存记录](../../cpu-cad-offline/offline-preparation.json)

有些量在进程中建立。曲面的多项式求值系数、子面片包围盒及其搜索索引在初始化时构建。积分点按最多八点分块，块的面积、面积矩、加权位置及法向线段包围盒在读入规则后计算，供后续姿态复用。前一步的候选窗口、命中点和可用的连通路径也属于运行时缓存。这里的持久化表只依赖零件本身，各步的相对位姿、承载区边界、受载深度和力矩由动力学计算。[面片编译](../../../../src/cad_compiled_chart.hpp) · [组块、查找、分组和积分](../../../../src/cad_patch_search.cpp)

## 五秒的时间花在哪里

正式运行用时 915.47 s，初始化 46.49 s。接触查询在两级并行执行时累计占用 799.64 s 墙钟。17 个触发局部布尔求交的主步累计 91.75 s，包含这 17 步的其他工作；整实体布尔回退为零。其余 49,983 个普通步累计 763.64 s。

| 普通步的两个接触对分阶段累加 | 累计 | 占下列四项之和 |
| --- | ---: | ---: |
| 划定承载范围并积分，得到面积、力臂、体积和中心 | 446.23 s | 49.0% |
| 检查局部接触是否连通并分组 | 206.79 s | 22.7% |
| 搜索并核实接触点 | 181.01 s | 19.9% |
| 粗筛候选 | 77.36 s | 8.5% |

分母为 911.39 个接触对累计秒，两级同时工作时各计一次。17 个回退步和初态均由逐步计数差分分离。全程粗筛窗口命中 188,419 次，重建 14,903 次。对已经找到的面对，当前实现仍循环扫描该面的积分块，将包围盒变换到对方坐标系，经检验后跳过、整块累计或逐点求深度。正式运行记下 1,482,789 个部分承载块和 462,420 个完全承载块；同厚度直接共享柱深的次数为零。[完整计数器](../depth-bounds/cad-bezier-bounds-run.json)

## 两段正常啮合的函数采样

Very Sleepy 0.91 对本机诊断用求解器的线程抽样，求解器以 MSVC Release 的 `/O2 /Ob2` 生成，并附调试符号。两段采样各 18 s，分别落在 0.6015–0.7181 s 和 3.0020–3.1210 s 仿真时间范围内。起止主步取自启动和退出采样器时的进度日志，略宽于实际取样区间。两段分别获得 24,960 和 24,000 个成功的线程样本，均包含空闲线程。

下表的分母只含调用栈可归属于 CAD 几何的样本时间权重。显式等待、休眠和其他调用另计，每条调用栈只分到一个入口。比例用于定位函数，不能乘以 915.47 s 得出整机墙钟。[原始早段采样](early.sleepy) · [原始晚段采样](late.sleepy) · [分母、计数与完整五秒诊断记录](profile.json)

| 调用 OCCT 线段与裁剪面求交 `IntCurvesFace_Intersector::Perform` 的来源 | 早段 | 晚段 |
| --- | ---: | ---: |
| 承载区积分中找材料法向的第一个出口 | 29.5% | 38.1% |
| 分组时检验两个接触点间的线段是否穿出实体 | 21.7% | 19.1% |
| 搜索时核实候选接触点的出口 | 9.1% | 9.1% |
| 合计 | **60.3%** | **66.3%** |

求交器对象本身已按工作线程和面缓存。反复发生的是针对新线段调用 `Perform`。深度界加速了承载积分中的一条路径；接触点搜索和分组仍各自需要检查穿越裁剪面的情况。采样中只归入 `DepthPacket` 的剩余工作占 2.6% 和 3.4%，热路径里同时出现 OCCT 内部包围比较、临时内存操作和曲面求交。另取初始化最初约 14 s 的样本，该窗口非等待样本权重的 89.2% 在 STEP 读入调用栈内；这是初始化前段的比例。[启动采样](setup.sleepy) · [线段求交与连通检查实现](../../../../src/cad_contact_regions.cpp)

采样版也完成全部 50,000 步，进程用时 1,016.32 s。两级承载状态与正式版逐帧相同。两次运行的接触批次为 50,089 和 50,095，轨迹哈希有差异；输出轴力矩 RMS 差为 0.0211 N·m，最大差 1.7357 N·m。正式速度对照采用无采样的 915.47 s。

## 为什么快速曲面求交会回退

在两级各 800 个已存档姿态上，从 Bézier 查询记录导致回退的分支，追踪到这条线段真正进入 OCCT 的位置，再计时 `Perform`。总调用数分别为 4,119 和 18,986，与无计数探针的同姿态对照完全一致。有效时间只覆盖内核调用，各线程的时间可以重叠；命中表示 OCCT 在同一张 CAD 面上报告至少一个交点，还需通过后续的深度、朝向、裁剪与遮挡检查。[逐原因、逐入口的调用次数、命中数和计时](fallbacks.json)

| 快速路径首先遇到的原因 | 一级回退次数 | 二级回退次数 | 二级 OCCT 报告有交点 | 二级 OCCT 内核累计时间 |
| --- | ---: | ---: | ---: | ---: |
| 由面片中心线性化得到的初值在当前参数小块边界上或外面 | 3,800 | 15,017 | 13,545 | 5.993 s |
| 整个参数小块的收缩界未通过 | 31 | 3,724 | 517 | 2.864 s |
| Newton 更新走出当前小块 | 77 | 212 | 194 | 0.088 s |
| 最终根的误差范围触及小块边界 | 211 | 33 | 33 | 0.018 s |

二级有 79.1% 的原生调用来自初值越界，另有 19.6% 来自整块收缩界。一级初值越界占 92.3%，3,800 次原生调用全部在该面找到交点。当前程序以单个 Bézier 参数小块为单位验证求交；任一候选小块无法判定，整张面的此次查询就可转交通用求交器。一个面可含多个小块，原生求交得到的交点可能位于邻块。把“初值在小块外”直接当成无接触会破坏这条逻辑。

首先值得验证的是在初值越界时同时检查邻块或用上一姿态的有效 UV 重新定位，在可能更早相交的块上保留排除检验。对收缩界未通过的块可试更细的局部界。可用同一批姿态复核原生调用次数、实际求交耗时和接触结果，再决定是否进入闭环速度对照。[现有参数域判定与整面回退](../../../../src/cad_bezier_ray.cpp)

## 复算

使用[原减速器场景和运行库](../README.md)。`$scene` 为同一份 `common-200.scene`，`$cache` 为填好的 CAD 缓存目录，`$runs` 为保存无采样五秒仿真原始 CSV 的目录，`$probe` 为正式版探测程序。函数采样使用带 PDB 的 `$exe` 和 x64 Very Sleepy 0.91 的 `$sleepy`。生成 PDB 时保持原 Release 的优化与浮点选项，新增编译选项 `/Z7` 和链接选项 `/DEBUG:FULL /OPT:REF /OPT:ICF /INCREMENTAL:NO`。

```powershell
$env:OMP_NUM_THREADS = "2"
$env:NC_CAD_CACHE_DIR = $cache
$archive = "results/aes/cpu-bezier"
$out = "$archive/hotspots"
python benchmarks/aes/cpu_cad_cache_audit.py $scene $probe $cache "$archive/depth-bounds/preprocessing.json" "$out/cache.json"
python benchmarks/aes/cpu_cad_hotspots.py $exe $scene $sleepy build/profile-run
python benchmarks/aes/cpu_cad_hotspot_report.py "$runs/cad-bezier-bounds" "$archive/depth-bounds/cad-bezier-bounds-run.json" build/profile-run "$out/profile.json" --scene $scene
```

在单独的诊断源码副本里应用[回退原因计数补丁](../../../../benchmarks/aes/cad_fallback_profile.patch)，重新编译 `nc_cad_probes`，得到 `$countingProbe`。生产求解器和上述采样用求解器均不带此补丁。每一级的 800 个姿态使用同一批参考轨迹；脚本校验调用总数与原程序一致。

```powershell
python benchmarks/aes/cpu_cad_fallback_counts.py $scene $archive $countingProbe "$out/fallbacks.json"
```
